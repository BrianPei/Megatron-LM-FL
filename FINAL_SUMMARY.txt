================================================================================
PILOT WORKFLOW USAGE
================================================================================

Test Command:
  gh workflow run all_tests_musa.yml \
    -f image_override='harbor.baai.ac.cn/flagscale/megatron-musa@sha256:<64-hex>' \
    -f expected_te_fl_commit='<40-hex-commit-sha>' \
    -f run_unit_tests=true \
    -f run_functional_tests=false

Inputs:
  - image_override: Optional, must be image@sha256:digest format
  - expected_te_fl_commit: Optional, 40 hex chars
  - run_unit_tests: Boolean (default true)
  - run_functional_tests: Boolean (default true)

Validation:
  - image_override format enforced: ^[^@]+@sha256:[0-9a-f]{64}$
  - Empty override falls back to .github/configs/musa.yml ci_image

================================================================================
RUNTIME VERIFICATION (7 STEPS)
================================================================================

Script: .github/scripts/verify_te_runtime.sh

Checks:
  1. Resolved container image (reports input)
  2. transformer_engine installation (path & version)
  3. Native extension presence (transformer_engine_torch or .pytorch)
  4. TE-FL commit verification (if expected_te_fl_commit provided)
  5. Platform implementation registration (TE_FL_PLATFORM env var)
  6. Operator backend selection (Linear operator instantiation)
  7. Platform-specific checks (CUDA/MUSA/device availability)

Failure modes:
  - Missing transformer_engine → EXIT 1
  - Missing native extension → EXIT 1
  - Commit mismatch (when expected provided) → EXIT 1
  - Linear import/instantiation failure → EXIT 1

Success output:
  >>> SUCCESS: TE-FL runtime verification passed
